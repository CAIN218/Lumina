# BrightSwitch

Windows用の常駐型モニター明るさ調整ツールです。
タスクバー右下(通知領域)のアイコンをクリックすると、接続中の各モニターの明るさを
モダンなスライダーで直接調整できます。

- タスクバーのアイコンをクリック → 各モニターの明るさスライダーがその場に表示
- アイコンを右クリック → 表示方法・挙動をON/OFFで切り替えられる設定メニュー
- DDC/CI対応の複数モニターをそれぞれ独立して(または連動させて)調整
- 調整後にはトースト通知で現在の明るさを表示(設定でON/OFF可)

## 対応環境

- Windows 10 / 11
- DDC/CI対応モニター(HDMI/DisplayPort接続の外部モニターの多くが対応)。
  ノートPCの内蔵ディスプレイはWindows標準の明るさ調整を使ってください(DDC/CI非対応)。
- お使いのモニターがDDC/CIに対応していない場合、パネルに「DDC/CI対応モニターが
  見つかりません」と表示されます。モニターのOSDメニューでDDC/CIを有効にできる
  場合があります。

## 使い方

### 1. 起動

`BrightSwitch.exe`(または`python brightness_switch.py`)を起動すると、タスクバー
右下の通知領域に太陽アイコンが常駐します。ウィンドウは表示されません。

### 2. 明るさを変える

通知領域のアイコンを**左クリック**すると、画面右下に各モニターのスライダーが
並んだパネルが開きます。スライダーをドラッグすると明るさが変わります。
パネルの外側をクリックすると閉じます。

### 3. 設定を変える

通知領域のアイコンを**右クリック**すると設定メニューが開きます。全てON/OFFの
トグルで、その場でチェックが切り替わります(保存ボタンなどは不要)。

| 項目 | 内容 |
|---|---|
| サインイン時に起動する | Windows起動時に自動でBrightSwitchを立ち上げる |
| 大きいスライダーを使う | パネルのスライダーを大きく表示する |
| 調整後の明るさを表示する | スライダーから指を離した時にトースト通知を出す |
| 現在の数字を表示する | パネルに各モニターの明るさを%表示する |
| 止まるまで変更を遅らせる | ONにするとドラッグ中は反映せず、指を離した時だけ実際に明るさを変更する(OFFの場合はドラッグ中も逐次反映) |
| 一斉に動かせるようにする | ONにするとどれか1つのスライダーを動かすと全モニターが連動して動く |

### 4. 終了方法

通知領域のアイコンを右クリックし、「終了」を選択してください。

## 設定ファイル

exeと同じフォルダに以下のファイルが作成されます。

- `app_config.txt` — 上記の設定(`key=value`形式)
- `error.log` — エラー発生時のログ(トラブル時の調査用)

## 開発者向け: ソースからのビルド

```
pip install -r requirements.txt
pip install pyinstaller
pyinstaller --noconfirm BrightSwitch.spec
```

`dist/BrightSwitch.exe` が生成されます。

## 今回スコープに含めなかったもの

参考にしたアプリ(Twinkle Trayなど)にある以下の機能は、今回は実装していません。

- **モニター配置に従って並べる**: 物理的なモニター配置とDDC/CI側のモニター
  列挙順を正しく対応付ける確証が取れなかったため、誤った対応付けをするより
  実装を見送った
- **調整可能な幅を変更可能にする**(モニターごとの最小/最大値の制限): 追加UIが
  必要になるため今回は見送り
- **コントラストを変更可能にする**: 使用しているライブラリ(`screen_brightness_control`)
  がコントラスト制御に対応していないため見送り(生のVCP経由で実装は可能だが、
  別途対応が必要)

## 設計メモ

AudioSwitcher(同シリーズの音声出力切り替えツール)と同じ設計方針を踏襲しつつ、
UIはタスクバー常駐のトレイアイコン中心に作り直した。

- トレイアイコン(pystray)は専用のメッセージループを持つため、Tkinterの
  mainloopとは別スレッドで動かしている。トレイ側のコールバック(クリック・
  メニュー選択)はpystrayのスレッドで呼ばれるため、Tk操作は全てキュー経由で
  mainloopに戻している
- パネルのスライダーはTkの標準Scaleウィジェットではなく、Canvasに角丸トラック
  とアクセントカラーの塗りを自前で描画するモダンなカスタム実装
- AudioSwitcherで踏んだ「低レベルフックのコールバック内で重い処理をすると
  無反応になる」教訓は、今回はグローバルホットキーを使わない設計にしたため
  該当しないが、DDC/CI通信(I2C経由で数十〜百ms程度かかることがある)は
  スライダーのドラッグイベントハンドラ内で直接行っているため、「止まるまで
  変更を遅らせる」をOFFにした状態で複数モニターを連動(一斉に動かせるように
  する)させると、ドラッグ中にややもたつく可能性がある
